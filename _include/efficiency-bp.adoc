== Mejores prácticas de eficiencia

[[aff-and-asa-defaults]]
=== Valores predeterminados de AFF y ASA

Los volúmenes creados en ONTAP que se ejecuta en sistemas AFF y los LUNs/espacios de nombres en sistemas ASA se aprovisionan en capa fina con todas las funciones de eficiencia en línea activadas. Aunque las bases de datos generalmente no se benefician de la deduplicación y pueden incluir datos no comprimibles, la configuración predeterminada es, no obstante, adecuada para casi todas las cargas de trabajo. ONTAP está diseñado para procesar de forma eficiente todo tipo de datos y patrones de E/S, independientemente de que supongan o no un ahorro. Los valores predeterminados solo deben cambiarse si se comprenden perfectamente los motivos y existe una ventaja para desviarse.



[[general-recommendations]]
=== Recomendaciones generales

* Si los volúmenes AFF, LUNs o espacios de nombres no están thin provisioned, debes desactivar todos los ajustes de eficiencia porque usar estas funciones no proporciona ningún ahorro y la combinación de thick provisioning con la eficiencia del espacio activada puede causar un comportamiento inesperado, incluidos errores de falta de espacio.
* Si los datos no están sujetos a sobrescrituras, como con backups o registros de transacciones de base de datos, puede lograr una mayor eficiencia habilitando TSSE con un bajo período de enfriamiento.
* Es posible que algunos archivos contengan una cantidad significativa de datos que no se puedan comprimir, por ejemplo, cuando la compresión ya está activada en el nivel de aplicación de los archivos está cifrada. Si se da alguna de estas situaciones, considere la posibilidad de deshabilitar la compresión para permitir un funcionamiento más eficiente en otros volúmenes que contengan datos comprimibles.
* No utilice la compresión 32KB ni la deduplicación con backups de bases de datos. Consulte la sección <<Compresión adaptativa>> para obtener más detalles.
